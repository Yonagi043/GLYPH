# TASK-03：跨文化感知实验与多语种问卷子系统

版本：`0.1.0-draft`
日期：2026-09-04
建议执行顺序：第三项；协议和合成链路可提前，正式刺激接入等待 TASK-01
系统角色：用真实受试者实验连接刺激、视觉形式与跨文化感知

## 1. 给执行 Agent 的任务指令

你负责把“设计问卷，剔除是否为母语的影响”完善为一个科学上可识别、工程上可运行的跨文化实验子系统。这里的“剔除”不能理解为删掉母语信息或只让所有人看陌生文字；正确目标是：

> 通过平衡抽样、同一刺激协议、母语/文字熟悉度测量、随机化和分层统计模型，分离视觉形式、文字系统、可读性、熟悉度与参与者背景的贡献，并检验母语相关交互。

你要交付问卷协议、四语界面、随机化/配额、去标识数据契约、质量控制、合成 dry-run 和统一系统接口。未经用户批准，不招募、联系或收集真实参与者数据。

开始时检查当前仓库和历史。现有 `human_rating` schema 与示例是早期通用契约，不等于问卷已经设计或实验系统已经实现。

## 2. 系统定位

本子系统负责：

- 冻结研究问题、实验条件、问卷版本和分析计划；
- 向不同母语/原生文字组呈现同一套可比刺激；
- 测量审美、高级感、现代感、可信、易读、陌生和品牌适配等感知结果；
- 测量母语、原生文字、识字程度、熟悉度、设计/书法训练和跨文化接触；
- 生成可复现的随机分配、试次日志、质量标记和去标识评分；
- 为联合分析提供真实、可审计而不是 AI 模拟的响应数据。

本子系统不负责：

- 用 Persona Agent 代替真实受试者；
- 宣布一个未经翻译等价性验证的量表跨文化可比；
- 把参与者国籍等同于母语或文字熟悉度；
- 把奖项身份、品牌知名度和作品说明泄漏进纯视觉盲评；
- 在没有伦理/数据管理批准时开始真实招募；
- 直接给出四条研究线的最终因果结论。

## 3. 核心研究设计

### 3.1 主要研究问题

最低回答：

1. 同一刺激在母语/原生文字使用者与非使用者之间，审美、高级、现代、可信、易读和陌生评分是否不同；
2. 加入 TASK-02 的视觉特征后，文字系统或书体标签是否仍有剩余关联；
3. 可读性、熟悉度、设计训练和文化接触是否解释或调节上述差异；
4. 纯视觉盲评与显式文化/来源标签条件是否不同；
5. WP4 汉字书体的结构差异和文化联想能否在实验条件中被区分。

其中第 4 项必须作为独立、预注册的实验条件或后续研究，不能在同一试次临时显示/隐藏标签后混为一个评分。

### 3.2 因子结构

最低参与者层变量：

- `mother_tongue_bcp47`：允许多值和主导语言；
- `native_scripts`：允许多文字系统，不以语言自动推断；
- 各目标文字的阅读/书写熟练度和接触频率；
- 居住地区和跨文化经历的粗粒度类别（避免不必要的精确位置）；
- 设计、字体排印、书法训练；
- 年龄段、教育层级等经伦理批准的最小必要背景；
- 设备和显示条件的非指纹化诊断信息。

最低刺激层变量：

- `stimulus_id`、writing system、style/font instance、content set；
- TASK-01 冻结的表示和 QC；
- `controlled_font_specimen`、`isolated_wordmark`、`han_style_specimen` 等刺激类型；
- 是否含可读语义、品牌线索、图形符号和生态背景；
- TASK-02 特征版本只用于分析，不在前端泄漏。

最低试次层变量：

- 呈现条件、顺序、block、随机化种子、开始/结束时间；
- 实际展示资产 SHA-256、CSS 像素大小和 viewport；
- 响应、响应时间、跳过/不适用、焦点丢失和质量标记；
- 不记录键盘原始输入、IP 或无必要的设备指纹。

### 3.3 抽样与分配

目标组至少围绕四种文字经验建立配额：拉丁、汉字、假名、韩文。语言和文字系统不是一一对应关系；双语/多语参与者允许单独分层，不得强塞进单一组。

不得要求每个参与者评价全部 375 张图片。实现**平衡不完全区组设计**或等价的约束随机化：

- 每人只看可承受数量的刺激；
- 每个刺激在各参与者组和呈现位置上近似平衡；
- 同一作品的近重复图不在同一参与者 block 中重复出现；
- 每个 block 混合文字系统，但控制连续同类和顺序效应；
- 设置跨版本锚点刺激，用于检查量表漂移；
- 分配算法和种子可复现，服务重启后不能重复发放或破坏配额；
- 参与者刷新/中断的恢复策略预先定义。

在正式样本量确定前，提供模拟/解析 power analysis 框架。不得虚构效应量；至少报告多个假设效应和组内相关下所需样本区间，并由用户在 `GATE-PARTICIPANTS` 前批准。

## 4. 问卷结构

### 4.1 模块顺序

建议默认顺序：

1. 研究信息与知情同意；
2. 资格和年龄门槛；
3. 语言、原生文字和熟练度；
4. 设计/书法训练与文化接触；
5. 设备校准和练习；
6. 随机化视觉评价 block；
7. 熟悉度/识别度检查（不得提前泄漏品牌）；
8. 注意力与数据质量检查；
9. 可选开放反馈；
10. 完成页和退出/撤回说明。

精确顺序须通过认知访谈/预测试决定并版本化，不能为了提高完成率而隐藏必要同意信息。

### 4.2 主要量表

主结果与四线文档一致：

- 美观 `aesthetic`
- 高级感 `premium`
- 现代感 `modern`
- 可信感 `trustworthy`
- 易读性 `legibility`
- 陌生感 `unfamiliarity`
- 品牌适配 `brand_fit`（只有提供冻结品类场景时适用）

量表必须为每种语言提供等价锚点和“不适用/无法判断”。`legibility` 对非母语文字不等于视觉清晰度，应同时测“能否读出/是否认识”和“视觉清晰”，或明确其中一个构念。

不要每张刺激都询问李婕的十个理论指标，这会造成严重疲劳和共同方法偏差。十项构念可用于：

- 选定子样本上的构念验证；
- 专家/设计训练者附加 block；
- 少量可理解维度（如平衡、结构、节奏）的独立实验；
- 联合分析中由视觉特征解释，而不是要求普通参与者逐项打分。

### 4.3 翻译与等价性

首版界面至少支持简体中文、英语、日语、韩语。每个版本必须：

- 具有稳定 `questionnaire_version` 和逐题 `item_id`；
- 保留源语言、翻译、回译/委员会审阅、认知访谈和变更记录；
- 不把机器翻译直接标记为已验证；
- 检查术语是否跨文化等价，尤其是“高级感”“可信”“陌生”和书法术语；
- 支持语言版本内 pilot，但跨组比较前执行测量等价性检查；
- 任何 wording 改变生成新版本，历史响应仍绑定旧版本。

## 5. 数据契约设计

### 5.1 保留现有 `human_rating`

现有记录继续表示“一位参与者对一个刺激的一次反应”，但先修复/澄清以下契约问题：

- `rating_scale=likert_1_7` 或 `likert_1_5` 时，当前评分字段仍允许 0–100，范围语义不一致；
- 单一 `native_script` 无法表达多文字系统背景；
- 缺少 `questionnaire_version`、`assignment_id`、`block_id`、`presentation_id` 和展示资产哈希；
- 缺少逐维度“不适用”和缺失原因；
- 缺少数据来源类型，必须机械禁止 synthetic/Persona 数据进入真人表；
- 一个对象中混放七个评分，不利于多语言 item 版本和部分量表。

先写 schema gap 说明。以新增可选字段、关联 schema 或新主版本解决，不得静默改变旧记录含义。历史示例须继续通过旧版本验证。

### 5.2 新增最小规范对象

建议至少新增：

1. `study_protocol`：研究问题、假设、因子、主要/次要结果、排除规则、样本量计划、分析公式、版本和批准状态；
2. `questionnaire_definition`：语言、item、量表、锚点、顺序、翻译证据和资产展示规则；
3. `participant_profile`：去标识背景变量；与联系/补偿信息物理分离；
4. `assignment`：参与者被分配到哪些 block/刺激、随机种子和配额快照；
5. `presentation_event`：实际呈现事实、响应时间和质量信号；
6. `consent_receipt`：只记录同意版本、时间和状态；不把签名/姓名放入研究仓库。

每个 schema 必须有版本、模板、fixture、验证器和外键测试。若不新增某个对象，必须说明现有对象如何无歧义表达同一事实。

### 5.3 隐私分区

```text
PII/联系/补偿系统（本任务不实现或独立受限）
        |
        | 单向映射，不进入 Git
        v
participant_id -> participant_profile -> assignment -> presentation/rating
```

- 不收集研究目的不需要的精确生日、地址、IP、账号或自由文本身份；
- 联系信息和研究响应使用不同存储与密钥；
- 原始真实响应进入被 Git 忽略的 `data/raw/participants/` 或受控数据库；
- 去标识导出仍需重识别风险检查；
- 撤回、保留期限、备份删除和访问控制进入数据管理计划；
- 日志不得记录完整响应正文、token、联系信息或 consent 页面输入。

## 6. 实验运行引擎

优先评估成熟的浏览器实验库（例如当前维护且许可兼容的 jsPsych）来处理试次、随机化和时间记录，不手写一个未经验证的实验引擎。若现有 Python/FastAPI 架构与库集成，应保持：

- 前端负责可访问呈现和本地试次状态；
- 后端负责冻结协议、分配、幂等提交、配额和审计；
- 规范导出符合 schema；
- 统一工作台通过公开服务接口读取状态，不直接写实验私有表。

不得把 LimeSurvey 或通用表单的存在视为视觉实验已完成。若选用第三方平台，必须验证随机化、刺激预加载、时间记录、数据驻留、版本冻结、导出完整性和许可；接受条款或付费属于 `GATE-TERMS`。

最低本机能力：

```text
glyph-experiment validate-study
glyph-experiment build-blocks --study-id ...
glyph-experiment serve --study-id ... --synthetic-only
glyph-experiment audit-assignments --study-id ...
glyph-experiment export --study-id ... --deidentified
glyph-experiment validate-handoff ...
```

真实收集默认锁死；必须在数据库和 UI 中显示 `synthetic_only=true`，只有用户通过人工门禁并提供本机批准配置后才能解锁。

## 7. 呈现与可访问性约束

- 实际呈现只读取 TASK-01 的冻结资产和哈希，加载失败时停止试次，不替换图片；
- 纯视觉条件隐藏文件名、奖项、年份、作者、品牌和来源 URL；
- 页面固定背景、图像容器、缩放规则和最小 viewport；不得非等比拉伸；
- 记录 CSS 展示尺寸和 device pixel ratio，但不构建设备指纹；
- 支持键盘操作、清楚焦点、屏幕阅读器可访问同意/背景题；视觉刺激本身提供研究需要的中性替代说明，不泄漏内容；
- 文本在四语和移动/桌面视口均不截断或重叠；
- 预加载完成后才计时；网络/渲染延迟与响应时间分开；
- 离开标签页、缩放异常或窗口过小时记录质量事件，不自动把参与者判为无效；
- 不在界面中展示视觉模型分数或研究假设。

## 8. 数据质量与排除

排除规则必须在真实数据前冻结。最低候选包括：

- 未同意、年龄/资格不符；
- 未完成最低试次数；
- 明确重复参与（只能使用伦理允许的最小机制）；
- 注意力检查失败；
- 大量过快响应、直线作答或不可用 viewport；
- 刺激加载/哈希失败；
- 参与者自报不理解问卷语言；
- 关键背景变量缺失。

每项规则输出 `exclude_from_analysis` 和机器可读原因，但保留原始记录和决定历史。不要用结果评分高低作为排除依据。质量规则在各语言/设备组上检查差异，避免对某一文化组系统性排除更多。

注意力检查不应要求识别非母语文字内容，也不应把文化知识当作认真程度。

## 9. 合成 dry-run 与 Persona 边界

允许使用程序生成的 synthetic participant 完成：

- 分配覆盖和配额测试；
- 中断/恢复、重试和幂等提交；
- 数据 schema、导出和联合分析接口；
- UI 自动化和多语言布局；
- 缺失、拒答、慢响应和异常设备 fixture。

所有合成记录必须位于 fixture/测试空间，带 `data_origin=synthetic`，使用不可与真人格式混淆的参与者前缀，并被 release/正式分析机械拒绝。Persona Agent 只能审查措辞和寻找歧义，其输出不得写入 `human_rating`，不得作为效应估计。

## 10. 统计预注册接口

TASK-03 不必实现最终分析引擎，但必须随 `study_protocol` 冻结：

- 主要结果、主要对比和多重比较策略；
- 分层结构：参与者、刺激，必要时作品/字体；
- `participant native script × stimulus script/style` 交互；
- 熟悉度、可读性、设计训练等预先指定协变量；
- 刺激分配概率/不平衡权重；
- 缺失和排除处理；
- ordinal/continuous 量表对应模型；
- 跨语言量表等价性检查；
- confirmatory 与 exploratory 分离；
- 数据冻结和分析 run 的哈希接口。

Agent 不得在看到真实结果后重命名主要结果或改变排除规则而不升版本。

## 11. 实施阶段

### 阶段 A：协议与 schema

- 将问题转成可证伪假设和 estimand；
- 完成现有 rating schema gap；
- 提交新 schema、模板、fixture、验证器和兼容策略；
- 冻结问卷 item ID 和翻译工作流。

### 阶段 B：约束随机化与合成引擎

- 使用许可明确的合成刺激或 TASK-01 fixture；
- 实现 block、配额、锚点、断点恢复和幂等提交；
- 用 property-based/模拟测试证明覆盖和平衡，不只人工看一份列表。

### 阶段 C：多语种界面

- 实现四语问卷、练习、试次和完成流程；
- 做桌面/移动、键盘和布局截图验证；
- 明确未完成人工翻译审核的状态。

### 阶段 D：正式刺激接入

- 只消费 TASK-01 通过 handoff 的刺激；
- 对展示哈希、权利层级、盲化和近重复做预检；
- 生成 pilot 刺激样本表，不擅自选择最终研究样本。

### 阶段 E：pilot-ready 门禁包

- 生成协议、问卷、翻译、功效模拟、隐私/数据管理、招募/配额、费用和停止条件；
- 提交 `GATE-ETHICS` 和 `GATE-PARTICIPANTS`；
- 明确停止，不收真实响应。

## 12. 自动测试与验收

### 12.1 自动测试

至少覆盖：

- schema 版本、外键、唯一 ID 和旧 rating 兼容；
- 量表类型与允许数值范围一致；
- 多母语/多原生文字表达；
- 问卷 item 和翻译版本不可变；
- 每组/每刺激/每位置的约束分配误差在冻结容差内；
- 同作品近重复不会进入同一 block；
- 刷新、中断、重复 POST、并发提交和恢复；
- 刺激哈希错误、资源加载失败和版本漂移；
- 不适用、拒答和缺失不被转为 0；
- synthetic 数据无法进入真实分析/release；
- PII 字段无法写入规范评分表或日志；
- 排除规则版本和决定历史；
- 四语缺失键、插值错误和文本溢出；
- 导出后逐行 schema 验证和计数一致。

### 12.2 最低可执行验收

1. 一个版本化 study protocol 明确假设、estimand、主要结果、抽样、随机化和分析公式；
2. 简中、英、日、韩四语问卷结构完整，并逐项显示翻译审核状态；
3. 参与者背景、问卷、分配、呈现和评分对象有规范 schema 与 fixture；
4. 许可 fixture 上至少 1000 个 synthetic participant dry-run 无丢试次、重复计数或配额越界；
5. 同一种子和输入生成相同分配摘要，不同种子仍满足约束；
6. 浏览器端桌面和移动流程通过自动化截图、交互和无重叠检查；
7. 去标识导出可被 TASK-05 读取，原始/联系信息不可通过该接口获得；
8. synthetic 响应被正式分析和 release 机械拒绝；
9. 全仓测试通过，真实收集开关保持锁定；
10. pilot-ready 报告明确伦理、翻译、专家、样本量和招募尚需哪些人工批准。

## 13. 对下游的交接

## 14. 强制停止条件

出现以下任一情况必须停止相关切片：

- 需要提交伦理申请、接受第三方平台条款、付费或招募真人；
- TASK-01 未通过的资产准备进入真实问卷；
- 四语翻译没有人工审核，却准备做跨文化比较；
- 样本量、主要结果或排除规则尚未冻结，却准备收数据；
- 需要记录不必要的 PII、IP 或设备指纹才能实现功能；
- 需要用 Persona/合成响应补足真实样本；
- 需要根据真实结果改变随机化、量表或主要假设；
- 用户本地修改无法安全保留。

停止时提交总蓝图规定的最终报告、门禁包和 `handoff_manifest.json`，不自动执行真实 pilot。
